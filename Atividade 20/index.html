🎓 Questão para Discussão — Onde a regra de negócio deve ficar?
▲

Pergunta: Onde a regra de negócio deve ficar: no frontend (JavaScript) ou no backend (PHP)? Por quê?

Conclusão Arquitetural: A regra de negócio deve ficar primordialmente no BACKEND (PHP). O frontend pode conter validações de conveniência visual, mas a autoridade definitiva e os cálculos de status devem residir no servidor.

Critério Regra no Frontend (JS) Regra no Backend (PHP) [Recomendado]
1. Segurança Vulnerável. O usuário pode alterar o código JavaScript ou variáveis pelo DevTools (Console) e aprovar a si mesmo. Segura. O código roda isolado no servidor e não pode ser adulterado pelo navegador do usuário.
2. Reutilização Duplicação. Se for criado um app mobile (Flutter/React Native) ou relatório, a regra precisa ser rescrita em cada um. Alta reutilização. Qualquer cliente (web, mobile, desktop, parceiros) consome a mesma API e recebe o status exato.
3. Consistência Risco de divergência. Um app mobile poderia usar nota 6.0 e o site 7.0, gerando dados inconsistentes. Garantia de consistência única (Single Source of Truth) para todo o sistema.
4. Manutenção Complexa. Caso a média mude para 6.0, seria necessário atualizar todas as aplicações clientes e limpar cache. Simples e centralizada. Modifica-se uma única linha no PHP e todos os clientes refletem a mudança na hora.
